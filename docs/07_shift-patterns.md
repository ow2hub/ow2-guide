# シフト生成エンジンとプリセット定義

「シフトリズム」の土台。ユーザーは**方式(型)を選ぶだけ**でカレンダーが自動展開され、
個別の日は後から手修正できる。工場勤務者は「4勤2休」等、周期で勤務を覚えているため、
"周期(サイクル)を回す"モデルが最もフィットする。

## ⚠️ 大前提(オーナー実態・2026-07 聞き取り)

- **勤務(昼/夜/休)は事前に確定していて本人は知っている**(＝スケジュールは固定・安定)。
  ただし**きれいな◯日周期で回るわけではない**(有給・増産・欠員で並びが毎回変わる)。実例:
  ```
  昼×4 → 休×1 → 夜×4 → 休×3 → 昼×2 → 休×2 → 夜×2 → 休×3 →(次)昼×4 …
  ```
- **早出(昼早出/夜早出)は不定**。事前には読めず、直前に決まる。
  → 早出/普通を**入力時に決めさせない**。勤務は「昼/夜/休」で入れ、早出は
  **各日ワンタップで後から切り替える属性**(既定=普通)にする。

### 設計への落とし込み
- 「サイクル自動展開」だけでは現実に合わない → **連続日数をまとめて置く"ブロック入力"を主役**に
  (確定した並びをサッと入れる)。固定周期の人には「繰り返し」をオプションで提供。
- 勤務種別は「昼/夜/休」の3つを基本に。**早出は開始時刻違いの"当日属性"**として別レイヤーで持つ。

## モデル(データ構造)

1. **勤務種別プロファイル**: 各勤務の名前と時間帯を定義(ユーザー編集可)
   - 例(オーナー): `昼(8:30–19:00)` `昼早出(8:00–18:30)` `夜(22:00–翌8:30)` `夜早出(21:00–翌8:00)` `休`
2. **入力方式は2つ**(同じデータに書き込む):
   - **(A) ブロック入力[主]**: 「昼勤 ×4日」「休 ×1日」…と連続日数をまとめて先頭から積む。
     不定期でもサッと入れられる。オーナーはこれ。繰り返しなし。
   - **(B) サイクル繰り返し[オプション]**: サイクル配列＋アンカー日で無限展開。固定周期の人向け。
3. **例外(手修正)**: 特定日だけ差し替え・追加(急な交替、有休の後付けなど)

これで「不定期のブロック積み上げ」から「2組2交代/3組2交代/2組3交代/4組3交代/日勤のみ」の
固定周期まで、同じデータ構造で表現できる。

## プリセット定義(選ぶだけで展開)

時間帯は方式ごとに標準値を入れ、ユーザーが自分の勤務先に合わせて微調整する。

### ① 2組2交代(2直2交代)= オーナーの系統(ただし並びは不定期)
- 2班で昼・夜をカバー。1回の拘束が長い(約10.5〜12h)。
- 勤務種別・標準時間: 昼 8:30–19:00 / 夜 22:00–翌8:30(+早出: 昼8:00–18:30 / 夜21:00–翌8:00)
- **固定サイクルではない**ため、ブロック入力(A)で運用するのが基本。
  参考の固定サイクル例(周期がある職場向け): `昼×5, 休, 休, 夜×5, 休, 休`(14日)
- ※早出バリエーションは勤務種別として持ち、個別日で差し替え

### ② 3組2交代(3直2交代)
- 3班で24時間・**土日休みなし**を最小人員で回す。拘束は長め(約12h)。
- サイクルは会社ごとに違うため**3サブプリセット**を用意:
  - a) `昼, 昼, 夜, 夜, 休, 休`(2昼2夜2休 / 6日周期)
  - b) `昼×4, 休, 休, 夜×4, 休, 休`(4昼2休4夜2休 / 12日周期)
  - c) `昼×3, 夜×3, 休×3`(3昼3夜3休 / 9日周期)
- 標準時間: 昼 8:00–20:00 / 夜 20:00–翌8:00(編集可)

### ③ 2組3交代
- 2班で早番/中番(遅番)/夜勤の3帯を回す。会社差が大きく休息が薄いためキツめ。
- 標準候補サイクル(要ユーザー確認・カスタム前提): `早, 中, 夜, 休` の繰り返し 等
- 標準時間: 早 6:00–14:00 / 中 14:00–22:00 / 夜 22:00–翌6:00(編集可)
- → 会社ごとの並びが多様なので、**カスタム周期ビルダーで組む導線**を主にする

### ④ 4組3交代(参考・継続操業で最多)
- 4班3交代。1日約8hで残業少なめ・体負担が比較的軽い。後ろ倒し回しが一般的。
- 標準サイクル(例): `早, 早, 中, 中, 夜, 夜, 休, 休`(2-2-2-2 / 8日周期)
- 標準時間: 早 6:00–14:00 / 中 14:00–22:00 / 夜 22:00–翌6:00

### ⑤ 日勤のみ / カスタム
- 日勤固定、または上記に当てはまらない人向けに、勤務種別と周期をゼロから組める
  **カスタム周期ビルダー**を用意(これが全方式の受け皿になる)。

## MVPでの優先順位

1. **ブロック入力(A)**(=不定期対応。オーナー実態。これが無いと現実に使えない。最優先)
2. **勤務種別プロファイルの編集**(昼/夜+早出の時間帯設定)と **2組2交代の勤務種別プリセット**
3. **サイクル繰り返し(B)** と 各方式プリセット(3組2交代の3サブ等)
4. **③2組3交代 / ④4組3交代**(プリセット+カスタム誘導)

理由: 「固定周期じゃない」人が現実に多い(オーナーもそう)。まず不定期をサッと入れられる
ブロック入力を完璧にする。固定周期プリセットは"あると嬉しい"の位置づけに変更。

## 添削してほしい点
- [x] 勤務の並び → **事前確定・本人把握済みだが◯日周期では回らない**。ブロック入力で対応と決定
- [x] 早出 → **不定(直前に決まる)**。各日ワンタップ切替の"当日属性"として実装と決定
- [ ] シフトは何日先まで職場から知らされる?(1週間先/1ヶ月先 等)→ 入力頻度の設計に効く
- [ ] 一番キツいと感じる並びは?(例:夜勤4連 / 夜勤明けから間を置かず昼勤 など)
