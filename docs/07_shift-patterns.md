# シフト生成エンジンとプリセット定義

「シフトリズム」の土台。ユーザーは**方式(型)を選ぶだけ**でカレンダーが自動展開され、
個別の日は後から手修正できる。工場勤務者は「4勤2休」等、周期で勤務を覚えているため、
"周期(サイクル)を回す"モデルが最もフィットする。

## モデル(データ構造)

1. **勤務種別プロファイル**: 各勤務の名前と時間帯を定義(ユーザー編集可)
   - 例(オーナー): `昼(8:30–19:00)` `昼早出(8:00–18:30)` `夜(22:00–翌8:30)` `夜早出(21:00–翌8:00)` `休`
2. **サイクル配列**: 1周期ぶんの勤務種別の並び。例 `[昼,昼,夜,夜,休,休]`
3. **アンカー日**: 「この日がサイクルの何番目か」を1点指定 → 前後に無限展開
4. **例外(手修正)**: 特定日だけ差し替え(有休・急な交替など)

これで「2組2交代」「3組2交代(各種)」「2組3交代」「4組3交代」「日勤のみ」から
**完全自由なカスタム周期**まで、同じ仕組みで表現できる。

---

## プリセット定義(選ぶだけで展開)

時間帯は方式ごとに標準値を入れ、ユーザーが自分の勤務先に合わせて微調整する。

### ① 2組2交代(2直2交代)
- 2班で昼・夜をカバー。多くは**土日休み or 繁忙期のみ**。1回の拘束が長い(約12h)。
- 標準サイクル(14日): `昼×5, 休, 休, 夜×5, 休, 休`(週替わりで昼→夜)
- 標準時間: 昼 8:30–19:00 / 夜 22:00–翌8:30(=オーナー実シフトがこの系統)
- ※早出バリエーション(昼早出/夜早出)を勤務種別に持たせて個別日で差し替え可

### ② 3組2交代(3直2交代)
- 3班で24時間・**土日休みなし**を最小人員で回す。拘束は長め(約12h)。
- サイクルは会社ごとに違うため**3サブプリセット**を用意:
  - a) `昼, 昼, 夜, 夜, 休, 休`(2昼2夜2休 / 6日周期)
  - b) `昼×4, 休, 休, 夜×4, 休, 休`(4昼2休4夜2休 / 12日周期)
  - c) `昼×3, 夜×3, 休×3`(3昼3夜3休 / 9日周期)
- 標準時間: 昼 8:00–20:00 / 夜 20:00–翌8:00(編集可)

### ③ 2組3交代
- 2班で早番/中番(遅番)/夜勤の3帯を回す。会社差が大きく休息が薄いためキツめ。
- 標準候補サイクル(要ユーザー確認・カスタム前提): `早, 中, 夜, 休` の繰り返し 等
- 標準時間: 早 6:00–14:00 / 中 14:00–22:00 / 夜 22:00–翌6:00(編集可)
- → 会社ごとの並びが多様なので、**カスタム周期ビルダーで組む導線**を主にする

### ④ 4組3交代(参考・継続操業で最多)
- 4班3交代。1日約8hで残業少なめ・体負担が比較的軽い。後ろ倒し回しが一般的。
- 標準サイクル(例): `早, 早, 中, 中, 夜, 夜, 休, 休`(2-2-2-2 / 8日周期)
- 標準時間: 早 6:00–14:00 / 中 14:00–22:00 / 夜 22:00–翌6:00

### ⑤ 日勤のみ / カスタム
- 日勤固定、または上記に当てはまらない人向けに、勤務種別と周期をゼロから組める
  **カスタム周期ビルダー**を用意(これが全方式の受け皿になる)。

---

## MVPでの優先順位

1. **① 2組2交代**(=オーナー実シフト。最優先で作り込む)
2. **② 3組2交代(3サブ)** と **⑤ カスタム周期ビルダー**(汎用の受け皿)
3. **③ 2組3交代** と **④ 4組3交代**(標準プリセット+カスタム誘導)

理由: まず当事者(オーナー)の系統を完璧に。カスタムビルダーを早く入れれば、
未対応の変則勤務も「自分で組める」ので取りこぼしが減る。
