# 30冊横断分析のやり方(実測値の作り方)

動画の数字をダミーから**本物**に差し替えるための手順とツール一式。

## 設計思想: AIに数えさせない

| 工程 | 担当 | 理由 |
|---|---|---|
| 本から主張を抜き出す | **AI** | 自然言語の読み取りは得意 |
| 同じ意味の主張をまとめる | **AI(人が最終確認)** | 表現ゆれの吸収は得意 |
| **何冊に登場したか数える** | **Python** | AIは数を間違える。集計は絶対にコードで |

AIに「何冊に出てきた?」と聞いた数字を動画に載せるのは危険です。
抽出だけAIにやらせ、**カウントは `aggregate.py` が決定論的に行います。**

---

## 全体の所要時間の目安

| 工程 | 時間 |
|---|---|
| ① 選書(30冊リスト作成) | 30分 |
| ② データ収集(1冊5〜10分 × 30) | **3〜5時間** ← ここが本体 |
| ③ AIで主張抽出(3回実行) | 1時間 |
| ④ 名寄せ(統合) | 1時間 |
| ⑤ 集計(スクリプト実行) | 1分 |
| ⑥ 動画の数字に反映 | 30分 |

初回は1日仕事。2本目からは②のテンプレが効いて半分になります。

---

## ① 選書 — `books.csv` を作る

Amazonの「時間術」「仕事術」等のカテゴリランキング上位から、**機械的に上から30冊**。
自分の好きな本を選ばないこと(結論が最初から歪みます)。動画内でもそう宣言します。

`books.csv` の形式(`books.sample.csv` をコピーして使う):

```csv
id,title,author,year,origin
b01,エッセンシャル思考,グレッグ・マキューン,2014,洋書
b02,...
```

`origin` は `和書` / `洋書`(翻訳書)。和洋の傾向比較に使います。

## ② データ収集 — `books/b01.md` を30個作る

**本文は絶対にコピーしない。** 使うのは以下だけ:

- 目次(Amazonの「なか見!検索」、出版社サイト、hontoなどに掲載されている範囲)
- 商品説明・紹介文・帯のコピー
- 自分の読書メモ・感想

`books/_template.md` をコピーして1冊1ファイル。ファイル名は `books.csv` の `id` と一致させます。

## ③ 主張の抽出 — AIに3回投げる

`prompts.md` の【抽出プロンプト】を使い、各冊のMarkdownを渡してJSONを受け取ります。
**同じ本に対して3回実行**し、`extracted/b01_run1.json` `..._run2.json` `..._run3.json` として保存。

3回まわす理由: AIの出力は毎回ブレるため。2回以上一致したものだけを採用して安定させます。
(この「3回まわして2回以上一致」という手続き自体が、動画で語れる信頼性の担保になります)

## ④ 名寄せ — 表現ゆれを統合する

抽出直後は「やらないことを決める」「捨てる勇気を持つ」「選択と集中」がバラバラに並びます。
`prompts.md` の【名寄せプロンプト】に全主張リストを渡し、正規化名への対応表を作ります。

出力を `canonical.json` として保存:

```json
{
  "捨てる勇気を持つ": "やらないことを決める",
  "選択と集中": "やらないことを決める"
}
```

**ここは必ず人間が目視で確認してください。** 別物を同じ扱いにすると結論が変わります。

## ⑤ 集計 — スクリプトを走らせる

```bash
cd analysis
python3 aggregate.py            # analysis/ 直下のデータを集計
python3 aggregate.py --dir path # 別ディレクトリを集計
```

出力:

- `report.md` — 全ランキング、和洋比較、1冊にしかない主張の一覧(動画の台本ネタになる)
- `video_numbers.py` — `build_video.py` の `SCENES` にそのまま貼れる数値ブロック

## ⑥ 動画に反映

`video_numbers.py` の中身を見ながら `build_video.py` の `SCENES` の数字と
`script.md` の記述を差し替え、ダミー表記の透かし(`WATERMARK`)を空にします。

---

## 先にパイプラインを試す(ダミーデータ)

実際の30冊を集める前に、一連の流れを空回ししておくと安心です。

```bash
python3 make_dummy.py            # dummy/ にダミーの書誌と抽出結果を生成
python3 aggregate.py --dir dummy # 集計してレポートを出力
```

このダミーは、仮動画 `video-prototype/` で使っている数値と一致するように作ってあります。
つまり**動画の数字は、この集計器を通して矛盾がないことを確認済み**です
(延べ251個 → 41種類 → 20冊以上は3種類 → 1冊限定19個 の内訳が破綻しない)。

生成される `dummy/report.md` を見ると、実データのときにどんな出力が得られるかがわかります。

---

## 数字が想定と違ったら

**それが一番おいしい展開です。** 「共通点は3つ」を期待して5つだった、早起きが実は多数派だった、
という結果になったら、その驚きをそのままフックにしてください。
仮説どおりにならなかった過程を見せることが、AIには作れない一次情報になります。

先に結論を決めて数字を合わせにいくのだけは、絶対にやめてください。
